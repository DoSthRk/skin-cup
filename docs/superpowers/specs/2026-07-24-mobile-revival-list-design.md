# 移动端复活赛紧凑列表设计

## 目标

复活赛候选皮肤数量明显多于单个小组。移动端不要求全部候选同屏，而是把每款皮肤压缩成一条横向选择行，多行纵向排列，减少滚动距离并保留完整的比较信息。

## 布局

- 仅在 `max-width: 38rem` 下生效。
- 每款皮肤仍是一个完整按钮：左侧约 `100 × 64px` 图片，右侧为名称、品质和特效标签。
- 每行目标高度约 `90–105px`，候选项按现有顺序纵向排列并允许页面滚动。
- 复用已经上线的小组赛紧凑卡片尺寸和文本规则，保证两个赛段视觉一致。
- 复活赛标题区一并压缩，增加首屏可见候选数量。
- “确认复活”在移动端固定于视口底部；列表保留底部空间，避免最后一项被按钮遮挡。

## 作用域

`RevivalStage` 增加 `stage--revival` 和 `skin-grid--revival` 两个类。移动端 CSS 同时匹配小组赛和复活赛专用类，桌面端、淘汰赛、首页、结果页和分享图均不改变。

复活候选数据、最多选择数量、取消选择、确认逻辑、按钮禁用状态和 `aria-pressed` 不改变。

## 验证

- 自动测试确认复活赛专用类存在。
- 原有四个复活名额选择与确认测试保持通过。
- `390 × 844` 下卡片高度约 `95px`，无横向溢出，首屏可见多条候选。
- 多行滚动正常，固定确认按钮不会覆盖最后一项。
- 桌面端复活赛仍使用原有大卡片网格。

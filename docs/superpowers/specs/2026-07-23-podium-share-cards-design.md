# 冠军分享图四名次卡片设计

## 目标

将冠军分享图底部的“夺冠之路”替换为“最终排名”，展示冠军、亚军、季军和殿军四款皮肤及其图片，同时保持现有赛事流程和 `1080 × 1350` 海报尺寸不变。

## 排名规则

- 冠军和亚军继续使用决赛结果。
- 不增加季军赛。
- 在半决赛中负于最终冠军的皮肤为季军。
- 在半决赛中负于最终亚军的皮肤为殿军。
- 如果半决赛数据无法完整推导四个名次，继续视为赛事结果数据不完整并拒绝生成。

## 海报布局

- 保留顶部品牌、武器名称、冠军大图和冠军名称。
- 压缩冠军信息区的垂直留白，为底部排名区提供空间。
- 删除“夺冠之路”标题及路径文字。
- 新增“最终排名”区域，使用两列两行卡片依次展示冠军、亚军、季军、殿军。
- 每张卡片包含名次、皮肤缩略图和皮肤名称；冠军使用红色强调，其他名次使用现有青色与中性色体系。
- 四张图片并行加载。单张图片无法加载时，仅在对应卡片内显示名次占位，不阻断整张 JPEG 生成。
- 页脚与现有下载、分享、自动预览流程保持不变。

## 数据与代码边界

- `deriveTournamentResult` 负责从现有淘汰赛对阵中推导 `thirdPlace` 和 `fourthPlace`，不修改 `TournamentState` 或存档结构。
- `buildShareImage` 负责加载四名次图片并绘制卡片。
- 完整淘汰赛晋级图不变。
- 冠军结果网页本身不新增四强列表，本次只调整自动生成的冠军分享图。

## 验证

- 单元测试确认季军是负于冠军的半决赛败者，殿军是负于亚军的半决赛败者。
- Canvas 测试确认不再绘制“夺冠之路”，改为绘制四个名次，并加载四款排名皮肤的图片。
- 图片加载失败时仍能导出 JPEG。
- 完整测试、类型检查、生产构建和真实浏览器图片预览全部通过后发布。

# 小组赛自动晋级设计

## 目标

移除所有武器小组赛中的“确认晋级”按钮。用户选择第一款皮肤后仍可取消或更换；点击第二款不同皮肤时，系统立即提交本组结果并进入下一步。

## 交互规则

- 小组赛提示改为“选择 2 款，选满后自动晋级”。
- 第一款皮肤仅进入选中状态，再次点击可取消。
- 点击第二款不同皮肤时立即提交，不短暂保存“已选满但未确认”的中间状态。
- 普通小组提交后进入下一组。
- 枪械最后一组提交后进入复活赛。
- 近战最后一组提交后直接进入 64 强淘汰赛。
- 复活赛的“确认复活”按钮保持不变。
- 顶部“撤销上一步”保持可用。自动提交的历史快照记录第二次点击前的状态，因此撤销后回到上一组，并保留第一款已选皮肤。

## 实现边界

`GroupStage` 只负责展示皮肤卡片和转发选择事件，不再接收确认回调或渲染确认按钮。

`App` 的小组选择处理器区分三种情况：

1. 点击已选皮肤：调用现有 `toggleGroupPick` 取消选择。
2. 点击后尚未达到两个名额：调用 `toggleGroupPick` 保存第一款选择。
3. 点击第二款不同皮肤：在当前状态上将两个 ID 显式传给 `confirmGroupPick`，直接提交。本次确认产生的撤销快照因此仍是第二次点击前的状态。

赛事引擎、皮肤池、赛制配置、存档版本和服务器部署结构均不改变。存档的因果校验继续验证实际晋级结果，并额外允许自动提交快照只保存第二次点击前的第一款选择；该选择必须属于随后实际晋级的两款之一。

## 验证

- 首页和四种武器入口保持不变。
- 任意小组选择第一款后仍停留在当前组。
- 选择第二款后自动进入下一组，页面不存在“确认晋级”按钮。
- 枪械最后一组自动进入复活赛。
- 近战最后一组自动进入 `1/32 决赛`。
- 自动提交后撤销，返回上一组并保留第一款选择。
- 自动提交后的存档可以正常重新载入，篡改过的历史快照仍会被拒绝。
- 复活赛确认、淘汰赛、分享图和存档回归测试保持通过。

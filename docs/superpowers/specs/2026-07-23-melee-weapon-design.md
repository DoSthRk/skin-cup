# 近战武器模块设计规范

## 目标

为 VALORANT-CUP 增加第四个武器入口「近战武器」。使用用户在 2026-07-23 完成的人工筛选结果，让全部 118 款获准皮肤进入小组赛，并由小组赛直接产生 64 强，不随机删减皮肤，不设置遗珠复活赛。

## 已确认决策

- 初始候选池为当前 Valorant-API 中品质至少为卓越、排除无畏契约 GO 系列后的 168 款近战皮肤。
- 用户通过可视化清单逐款筛选，最终保留 118 款、排除 50 款。
- 最终名单以稳定 UUID 固化，见 `2026-07-23-melee-selection.json`。
- 新发布的近战皮肤默认不加入，必须重新经过人工审核。
- 赛制采用 32 个小组：22 组四选二、10 组三选二，共产生 64 名晋级者。
- 近战模块取消遗珠复活赛，小组赛结束后直接进入 64 强淘汰赛。
- 首页近战入口暂用「紫金爪刀」作为代表皮肤，沿用现有武器卡视觉体系。

## 范围

### 包含

- 增加 `melee` 武器类型、标签、目录配置与首页入口。
- 将人工批准的 118 个 UUID 接入目录同步和严格计数校验。
- 扩展赛事引擎，使 `wildcardSlots = 0` 成为合法配置。
- 支持小组赛直接创建淘汰赛，不显示遗珠复活页面。
- 支持 64 强的轮次过场、冠军结果图和完整淘汰赛晋级图。
- 更新首页四卡布局、测试与 README。

### 不包含

- 将近战按爪刀、蝴蝶刀、战斧等外形拆成多个入口。
- 在线后台、账号系统、排行榜或远程赛果链接。
- 自动批准以后新增的近战皮肤。
- 为皮肤增加检视视频或额外媒体详情页。
- 修改狂徒、幻影和正义的现有皮肤池及赛制。

## 数据设计

### 类型

`WeaponId` 增加 `melee`，`WeaponLabel` 增加 `近战武器`。生成后的每个近战 `Skin` 与现有枪械皮肤使用相同结构。

### 人工准入名单

`2026-07-23-melee-selection.json` 是本次筛选的审计快照。实现时将其中 118 个 UUID 转为同步策略使用的只读集合。

近战准入必须同时满足：

1. UUID 位于人工批准集合。
2. 上游武器类型为「近战武器」。
3. 品质等级至少为卓越。
4. 名称不匹配无畏契约 GO / VALORANT GO。

API 特效标签只用于展示，不再决定近战是否入围。这样既保留用户批准的特殊检视边界皮肤，也不会自动加入未来新皮肤。

### 同步校验

同步脚本完成后必须得到：

```text
狂徒: 42
幻影: 36
正义: 24
近战武器: 118
```

同步脚本必须校验批准 UUID 总数、重复 ID、上游缺失 ID 和最终计数。任何不一致都应失败，并继续保持原子写入，不能用不完整目录覆盖现有生成文件。

## 赛制设计

### 配置

```ts
melee: {
  label: '近战武器',
  expectedCount: 118,
  groupSizes: [
    ...Array(22).fill(4),
    ...Array(10).fill(3),
  ],
  picksPerGroup: 2,
  wildcardSlots: 0,
  bracketSize: 64,
}
```

分组引擎继续按品级均衡分配，并使用现有种子随机顺序。32 个组的展示顺序可以混排三人组和四人组，避免最后连续出现较小组；无论顺序如何，总容量必须保持 118。

### 阶段转换

最后一个小组确认后：

1. 校验累计晋级者恰好为 64。
2. 使用现有种子洗牌生成 64 强首轮对阵。
3. 直接把阶段切换为 `knockout`。
4. 显示「64 强 / 1/32 决赛」轮次过场。

`wildcardSlots > 0` 的现有三类武器继续进入 `revival`，行为不变。`wildcardSlots = 0` 时，进度计算不计入复活赛动作。

### 淘汰赛

64 强共有 6 轮、63 场对决：

1. 1/32 决赛
2. 1/16 决赛
3. 1/8 决赛
4. 1/4 决赛
5. 半决赛
6. 决赛

冠军页继续自动生成冠军结果图和完整淘汰赛晋级图，并提供下载和系统分享按钮。

## 首页与视觉

- 首页新增第四张「近战武器」卡片，显示 `118 款特效皮肤`。
- 代表皮肤使用「紫金爪刀」PNG，图片加载失败时沿用现有占位行为。
- 宽屏使用四列；中等屏幕优先两列；手机保持单列，避免卡片和标题过度压缩。
- 小组赛、淘汰赛和冠军页复用现有组件，不新增近战专属视觉分支。

## 存储与兼容

- 继续使用 `skin-cup:v1` 本地存档键。
- 新增的 `weapon: 'melee'` 与现有快照结构兼容，无需迁移枪械赛事存档。
- 恢复存档时仍通过生成目录校验皮肤 ID；目录不完整时拒绝恢复无效状态。
- 狂徒、幻影和正义的当前存档及流程不受影响。

## 错误处理

- 上游请求失败、结构异常或近战批准 UUID 缺失时，同步命令失败。
- 118 款计数不匹配时不写入生成目录。
- 赛事配置若不能由小组晋级数填满 64 强，启动时抛出配置错误。
- 单张皮肤图片加载失败只显示占位，不阻断选择。
- 64 强晋级图生成失败时保留冠军页，并显示可重试的下载错误。

## 测试与验收

- 目录策略：118 个批准 UUID 全部入围；未批准近战、新皮肤和 GO 系列不入围。
- 同步：四种武器计数精确为 42、36、24、118。
- 配置：22 个四人组加10个三人组，总人数118，每组晋级2人，总晋级64人。
- 状态转换：近战最后一个小组确认后直接进入淘汰赛；现有枪械仍进入复活赛。
- 进度：近战总动作不包含复活赛步骤。
- 首页：显示第四张近战卡及118款计数，窄屏和宽屏布局可用。
- 赛程：64强所有轮次名称、撤销、续赛和冠军结果正确。
- 分享：64强冠军结果图及完整晋级图能自动生成并下载。
- 回归：现有测试、类型检查和生产构建通过。

## 发布

实施完成后恢复并保留现有双发布构建链，不能采用 Kimi 删除 `.openai/hosting.json`、删除 `prepare-sites-build.mjs` 或把服务器目录改为裸 `dist` 的未提交方案。发布继续使用现有 `dist/client` 静态目录，并分别验证自有服务器域名和 Sites 版本。
